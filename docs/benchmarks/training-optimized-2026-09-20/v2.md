# Optimized preview 2 — manager validation

Runtime source: `6012a536b8602d1b1b10a6ab581c2d30b880429d`, prerelease
`v0.15.0-myria.opt.2`. Baseline source remains `289ec383`. Both comparison
executables use the same manager build environment (Rust 1.94, HiGHS 1.13.1,
release profile). Binary hashes and commands are recorded in the adjacent JSON.
Runs were serial; existing Myria services remained running and were not changed.
The manager is shared, so timings include ordinary background-load uncertainty.

## Changes

- By-node DCS uses a block-local resident set and canonical per-opening outcomes.
- Optional adaptive DCS batches double up to a validated ceiling.
- Optional complete-state deduplication keeps one representative per node/iteration.
- Optional exploration-envelope audits grow a node's minimum backward budget.
  They retain all probe cuts and measure a local counterfactual, not global error.
  Resume after iteration 1 uses full coverage because audit history is not persisted.
- Frozen HiGHS backward matrices are reused within a node dispatch for the same
  child; solver basis, factorization and pricing history are cleared between units.
  Other backends retain their reload path. Arbitrary cross-point bases are not reused.

All controls are opt-in except frozen-matrix reuse and the previously shipped
exact DCS scoring/fallback changes. DCS only uses by-node when explicitly selected.

## Comparison protocol

`examples/4ree`, sampled training, one MPI rank, four threads unless specified.
CVaR alpha 0.15, lambda 0.4; LML1 frequency 1 or DCS with unbounded candidate recency.
Point-budget arms use initial points = forwards/4, two exploratory points, a
complete pass every four iterations and full refinement from floor(2*iterations/3).
Preview 2 enables deduplication and audit tolerance 0.01 in that arm. The separate
`dedup-only` comparison sets `full_from_iteration=1`, retaining every distinct state.
DCS candidate arms additionally use a batch ceiling of 80 (initial batch 20).

Each comparison evaluates 256 common out-of-sample scenarios, simulation seed
8675309. Timing repetitions keep the training seed fixed; seeds 7 and 91 are
independent training replications. Paired cost intervals condition on the trained
policies. Deficit and terminal storage are also retained in the summaries.
Neither these intervals nor lower-bound stability certify nested conditional risk
or operational non-inferiority across representative decks.

## Main result

For 40 iterations × 96 forwards, seed 42, three repetitions:

| Mode | Median training | LP solves | Cost difference | Deficit difference | Terminal storage difference |
|---|---:|---:|---:|---:|---:|
| Baseline | 38.749 s | 468,880 | reference | reference | reference |
| Preview, all points | 38.201 s | 468,880 | 0% | 0% | 0% |
| Preview, audited selection + dedup | 28.218 s | 341,950 | -0.0970% | -0.7500% | -1.7052% |

The selected mode reduced training time by 27.18%; total wall time fell from
39.766 s to 29.189 s. Its paired cost-difference 95% interval was
[-0.1649%, -0.0291%]. The exhaustive mode's 1.41% training reduction is small and
should not be generalized to larger cases. It reproduced the recorded lower
bound, cuts, LP count and simulation metrics exactly on this comparison.

## Scope against the six investigation fronts

| Front | Current scope |
|---|---|
| Profiling/configuration | Isolated harness, common scenarios, timing repetitions, worker/block/frequency sweeps; no automatic tuner |
| DCS | Partial top-k, matrix borrowing, complete fallback, adaptive batches and by-node support |
| Backward point selection | Progressive budget, diversity/exploration, exact-state dedup, local feedback, periodic/final coverage; no global certificate |
| Progressive forward trajectories | Not implemented |
| LP/base reuse across points | Matrix reuse with cold solver reset; no arbitrary cross-point basis reuse |
| Inexact cuts/opening partitions | Not implemented; requires explicit dual-error and conditional-risk treatment |

Thus four fronts have implementation, with the limits above; this is not a claim
that all six research fronts are complete.

## Verification

Manager debug-profile tests passed: 2,340 SDDP unit tests (one existing ignored),
1,766 I/O unit tests, 93 solver tests, all 41 MPI-wire/integration tests under
`test-support,slow-tests`, and selected-point CVaR refinement with 1/4 threads.
The MPI tests here use local/stub communicators, not a real multi-process launch.

The obsolete unit assertion forcing DCS to by-scenario was removed because that
fallback no longer exists. Replacement integration tests exercise actual by-node

between schedulers. Different warm chains may land on different valid vertices;

Strict Clippy was blocked by existing warnings outside this change. Ordinary

## Additional replications and DCS limitation

| Comparison | Baseline training | Candidate exhaustive | Candidate selected | Selected reduction | Selected cost difference |
|---|---:|---:|---:|---:|---:|
| DCS by-node block 5, 24 × 48, three repeats | 21.007 s | 26.355 s | 18.748 s | 10.75% | -0.0379% |
| LML1 seed 7, 30 × 64, one repeat | 17.434 s | 17.407 s | 14.356 s | 17.66% | +0.0574% |
| LML1 seed 91, 30 × 64, one repeat | 16.960 s | 16.394 s | 12.573 s | 25.87% | -0.0323% |

DCS by-node alone was 25.46% slower than the old by-scenario fallback in this
compact case, despite retaining all eligible rows. More block resets shorten warm
chains; the optional batch ceiling did not offset this cost. Do not enable by-node
DCS indiscriminately. The sampled-point combination was faster but does not turn
this scheduler result into a universal speedup. Its exhaustive policy had small
cost/deficit differences, recorded in the JSON, because warm-chain changes can
alter finite-iteration cut trajectories.

The seed-7 selected policy's cost increased by 0.0574%; deficit decreased by about
0.0464%. Seed 91 cost decreased by 0.0323% and deficit by about 0.1348%. These are
small observed changes, not proof that there is no deterioration in every metric.
No operational acceptance margin was chosen after looking at these results.

## Every distinct state, without point thinning

Three repetitions, CVaR/LML1, 40 × 96, seed 42: median training 38.417 →
32.708 seconds (14.86% reduction); LPs 468,880 → 400,400. The mode uses
`deduplicate: true, full_from_iteration: 1`, with no audit controller. Every
bit-distinct state is still solved. Mean simulated cost changed -0.0417%, deficit
-0.2393% and terminal storage
-1.9277%.

Duplicate removal changes cut identities/multiplicities and later LML1 pruning,
so it need not reproduce the exact finite-iteration policy. The measured cost
interval [-0.1046%, +0.0212%] and storage difference should accompany the timing
claim. This is a more conservative first experiment than thinning distinct points,
not a claim of universal non-inferiority.

## Configuration sweep

Single repetitions, 24 × 48, CVaR/LML1, every point, in-sample simulation.
Training seconds: by-scenario threads 1/2/4/8 = 30.672 / 15.605 / 8.699 / 4.841.
All four lower bounds were bit-identical. The 4→8 improvement (44.35%) uses
existing parallelism; it is not a code-only preview speedup and has not been
measured in combination with the 27.18% selected-point gain.

At four threads, by-node block sizes 5/10/20 took 8.650 / 8.621 / 8.588 seconds.
These are small differences and different warm chains; one repetition cannot
establish a preferred block size. LML1 frequency 5 took 11.117 seconds versus
8.699 for frequency 1. Do not assume less frequent pruning is faster.

resume before the configured full-refinement iteration. The release schema was
regenerated and compared without drift. Final ordinary Clippy completed; remaining
